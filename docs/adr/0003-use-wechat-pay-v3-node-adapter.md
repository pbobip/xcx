# 使用普通直连微信支付 APIv3 Node Adapter

本项目按企业主体、单商户自营模式接入普通直连微信支付，不采用服务商、特约商户或平台收付通模型。小程序 AppID 固定为 `wx373cd5ed5680a30d`；商户号与 AppID 的绑定关系、支付权限和退款权限必须在真实联调前由微信后台验证，代码不得假设“企业 AppID 已申请”就等于支付能力已开通。

支付继续运行在现有 Node.js 微信云函数架构中。`payment` 是一个深模块，外部只暴露预支付、查单、关单、退款和对账动作；支付通知与退款通知通过独立 HTTPS 路径进入同一模块。微信支付属于不可控的真实外部依赖，因此模块在内部 seam 接受 `wechatPay` Adapter：正式 Adapter 按微信支付 APIv3 文档实现，测试 Adapter 覆盖成功、失败、延迟、重复和乱序结果。

正式环境默认使用微信支付公钥模式验证响应和通知签名。商户号、商户私钥、商户证书序列号、APIv3 密钥、微信支付公钥 ID、公钥内容及通知地址只允许从云端安全配置读取；缺失时支付模块必须拒绝启动真实支付，不得回退为测试付款或把密钥写入普通数据库、日志、前端及版本库。

顾客端 `wx.requestPayment` 的返回值只表示前端支付流程结果，不是付款真值。只有通过验签通知或主动查单得到的微信结果才可改变支付状态。支付、退款、优惠券、履约状态和日志变化必须在云数据库事务内完成，并分别保持支付状态、履约状态和售后状态。
